# AutoFlex — интернет-магазин автоаксессуаров и тюнинга

Витрина и панель управления на Next.js 16 (App Router), React 19, TypeScript и Tailwind CSS 4.
Структура страниц повторяет ddaudio.com.ua, визуальный стиль — брендбук AutoFlex
(цвета, шрифты Inter + Exo 2, кнопки, поля, паттерны). Язык интерфейса — украинский.
База данных — MongoDB Atlas. Каталог — фид поставщика DD Tuning / DD Audio
(103 658 позиций прайса → 87 035 товаров, 22 группы и 236 категорий, 57 брендов,
100 марок и 1 864 модели авто), магазин работает по дропшиппингу.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000, админка — http://localhost:3000/admin
npm run build      # production-сборка
npm start          # запуск собранной версии
npm run lint
npm run typecheck
npm test           # vitest: маппинг фида, запросы каталога, домен, авторизация, заказы
```

Нужен Node.js 20.19 или новее (проект разрабатывается на Node 24).

Без `MONGODB_URI` в режиме разработки автоматически поднимается локальный MongoDB
(`mongodb-memory-server`, при первом запуске скачивает бинарник ~300 МБ); данные лежат в
`./data/mongo` и переживают перезапуск (путь меняется переменной `LOCAL_MONGO_PATH`).
Запущенный экземпляр публикует свой адрес в `./data/local-mongo.json`, поэтому второй процесс
(например `next build` рядом с работающим `next dev`) подключается к нему, а не падает на
блокировке каталога данных. В production локальная база запрещена; чтобы собрать или запустить
production-версию локально без Atlas, задайте `ALLOW_LOCAL_DB=true`.

В пустую базу в development заливаются демо-данные для админки (заказы за два месяца,
поставщики с прайсами, клиенты, заявки, отзывы на модерации), а без токена поставщика —
небольшой демо-каталог.

## Админка (/admin)

Полноценный бэк-офис для дропшиппинга: дашборд, заказы (статусы, оплата, ТТН и отслеживание
Новой Почты, таймлайн, печать, шаблоны сообщений покупателю), закупки у поставщиков,
поставщики с прайс-листами (импорт CSV), заявки с сайта, клиенты, каталог (товары поставщика
с вариантами, правки цен/наличия/описаний поверх фида, скрытие, свои товары, категории,
бренды), модерация отзывов, акции и FAQ, настройки магазина, пользователи с ролями, журнал
действий и раздел «Постачальник DD» (синхронизация каталога с живым прогрессом и историей,
политика цен, курсы валют, пересчёт цен).

Первый вход: откройте `/admin/login` на пустой базе и создайте аккаунт владельца, либо
задайте `ADMIN_EMAIL` и `ADMIN_PASSWORD` перед первым запуском. Роли: владелец (всё),
менеджер (операции, каталог, контент), просмотр (только чтение и экспорт).

Проектные описания и соглашения: `docs/superpowers/specs/2026-10-05-admin-panel-design.md`
(админка) и `docs/superpowers/specs/2026-10-05-ddtuning-catalog-design.md` (каталог поставщика).

## Кабинет покупателя (/account)

Регистрация — номер телефона, e-mail и пароль (дважды); вход — телефон или e-mail на выбор и пароль.
Аккаунт привязывается к карточке клиента в CRM по номеру телефона: прошлые заказы с этим номером
сразу видны в кабинете, новые заказы авторизованного покупателя попадают туда же. В кабинете —
заказы со статусами и номерами ТТН, данные для оформления (подставляются в чекаут), смена пароля,
выбранное авто. Сессии хранятся в базе (`account_sessions`, 30 дней), cookie `af_user` только
httpOnly, пароли — scrypt, вход ограничен 8 неудачными попытками за 15 минут. Восстановление пароля
по e-mail/SMS не реализовано (нужен провайдер рассылки): временный пароль выдаёт менеджер в карточке
клиента в админке, покупатель меняет его в кабинете.

## Что настроить перед запуском в продакшен

| Что | Где |
| --- | --- |
| Строка подключения к MongoDB Atlas (обязательно в production) | `.env.local` → `MONGODB_URI`, `MONGODB_DB` |
| Токен партнёрского API DD Tuning (https://ddtuning.com.ua/developers.html) | `.env.local` → `DDTUNING_API_TOKEN` |
| Секрет cron-маршрута синхронизации и расписание (раз в час) | `.env.local` → `CRON_SECRET`; cron на `GET /api/cron/ddtuning-sync` |
| Аккаунт владельца админки | `/admin/login` при первом запуске или `ADMIN_EMAIL` + `ADMIN_PASSWORD` |
| Телефон, e-mail, график, мессенджеры, соцсети | `src/lib/site.ts` |
| Реквизиты продавца для оферты и политики конфиденциальности (сейчас заглушки) | `src/lib/site.ts` → `legal` |
| Порог бесплатной доставки (`0` — доставку всегда оплачивает покупатель) | `src/lib/site.ts` → `freeDeliveryFrom` |
| Адрес сайта для canonical, sitemap и Open Graph | `.env.local` → `NEXT_PUBLIC_SITE_URL` |
| Дублирование заказов и заявок менеджерам | `.env.local` → `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` и/или `ORDER_WEBHOOK_URL` |
| Способы доставки и оплаты, наценки, шаблоны сообщений, ключ API Новой Почты | админка → Налаштування |
| Политика цен на товары поставщика (розница / себестоимость + наценка, округление), курсы НБУ | админка → Постачальник DD |
| Демо-данные (по умолчанию заливаются только в development) | `ADMIN_SEED_DEMO=true/false` |

Скопируйте `.env.example` в `.env.local` и заполните. Заказы и заявки сохраняются в базе и
попадают в админку всегда; Telegram и вебхук — дополнительный канал уведомлений.

Если на машине разработчика драйвер падает с `querySrv ECONNREFUSED` (резолвер Node не отвечает на
SRV-запросы), возьмите в Atlas строку подключения без `+srv` («Legacy URI String»); на Vercel подходит
обычная `mongodb+srv://`.

Размер базы с полным каталогом — около 400 МБ данных плюс 40 МБ индексов, поэтому бесплатный
кластер Atlas M0 (512 МБ) впритык: берите Flex или M2 и выше. На Vercel cron задаётся в
`vercel.json` / `vercel.ts` (`{ "path": "/api/cron/ddtuning-sync", "schedule": "0 * * * *" }`);
Vercel сам передаёт `Authorization: Bearer <CRON_SECRET>`.

Тексты оферты и политики конфиденциальности — типовые шаблоны, их стоит показать юристу.

## Деплой (Vercel)

Боевая версия развёрнута на Vercel: проект `auto-flex-client` (аккаунт nazary001s-projects), домен
https://avtoflex.com (www перенаправляется на apex), технический адрес https://auto-flex-client.vercel.app,
функции в регионе Франкфурт `fra1`; база — MongoDB Atlas (кластер `autoflex`, Франкфурт). Проект связан с
GitHub `nazary001/auto-flex-client`: пуш в `main` автоматически собирает и публикует production. Переменные production в Vercel: `MONGODB_URI` (строка `mongodb+srv://`),
`MONGODB_DB`, `DDTUNING_API_TOKEN`, `CRON_SECRET`, `NEXT_PUBLIC_SITE_URL`, `MONGODB_STORAGE_LIMIT_MB`
(квота кластера Atlas в МБ: 5120 для Flex; синхронизация проверяет свободное место перед записью), а также
`MONGOMS_DISABLE_POSTINSTALL=1`, чтобы при установке зависимостей не скачивался локальный MongoDB.
`vercel.json` задаёт фреймворк, регион и cron синхронизации каталога (раз в сутки в 03:00 UTC —
ограничение тарифа Hobby; на Pro можно поставить ежечасно). Пароль пользователя Atlas и секрет cron
хранятся в `.env.local` (`CRON_SECRET_PRODUCTION`).

DNS домена avtoflex.com ведётся у регистратора (Namecheap): его неймсерверы должны указывать на
`ns1.vercel-dns.com` и `ns2.vercel-dns.com` (либо A-запись `76.76.21.21` для apex и CNAME
`cname.vercel-dns.com` для www). `NEXT_PUBLIC_SITE_URL` уже равен https://avtoflex.com.

## Каталог и поставщик DD Tuning

Источник правды — коллекции MongoDB `products`, `categories`, `brands`, `makes`, `models`;
все страницы читают их через асинхронные функции `src/lib/catalog.ts`. Справочники
(категории, бренды, марки, модели) кешируются в памяти процесса на 60 секунд, товары всегда
запрашиваются из базы (текстовый индекс для поиска, фасеты через агрегации).

Синхронизация (`src/lib/server/suppliers/ddtuning/`) идёт фазами и умеет продолжаться после
обрыва: курсы НБУ → категории → розничный прайс → оптовый прайс → сборка товаров →
справочники → предложения поставщика → финализация. Запуск — кнопка в админке или
`GET /api/cron/ddtuning-sync` (`Authorization: Bearer CRON_SECRET`; `?force=1` игнорирует
выключенную автосинхронизацию, `?rebuild=1` только пересчитывает цены и наличие,
`?content=reset` заново заливает акции и FAQ под ассортимент).

Что делает маппинг (`mapping.ts`, покрыт тестами):

- позиции с одинаковым `parent` становятся одним товаром с вариантами (цена, наличие, фото и
  артикул у каждого варианта свои);
- `quantity` у поставщика — это 0/1 (есть / нет), а не остаток: «в наличии», «под заказ»
  (склады «в дорозі» / «уточнюйте») или «нет в наличии»;
- цена по умолчанию — розничная цена поставщика (акции поставщика переносятся с датами),
  режим «себестоимость + наценка» и округление настраиваются в админке; себестоимость берётся
  из оптового прайса в EUR/USD/UAH по курсу НБУ, а строки с условной ценой 1 USD / 1 EUR
  (кованые диски, обвесы с договорной ценой) себестоимостью не считаются;
- марка и модель с годами разбираются из строки `model`, универсальные товары помечаются;
- 22 группы и 236 категорий поставщика переведены в `src/data/ddtuning/category-names.uk.ts`,
  у групп есть иконки, иллюстрации категорий — `public/illustrations/dd-<icon>.svg`;
- правки из админки (`local` на документе: цена, наличие, описание, скрытие) переживают
  синхронизации; «Скинути зміни» возвращает данные поставщика.

Фото товаров отдаются с хостов поставщика (разрешены в `next.config.ts` → `images.remotePatterns`);
пока фото нет, показывается иллюстрация категории.

SEO: `app/sitemap.ts` режет каталог на файлы по 20 000 адресов (`/sitemap/<id>.xml`),
индекс — `/sitemap-index.xml` (на него указывает `robots.txt`), страницы товаров
перегенерируются раз в 10 минут (ISR).

## Как устроен проект

```
src/app/(store)          витрина: главная, каталог, товар, подбор по авто, бренды, поиск,
                         корзина, оформление, избранное, кабинет, акции, блог, инфо-страницы
src/app/(admin)/admin    админка: вход, оболочка (сайдбар + верхняя панель) и все разделы
src/app/api              публичное API: заказ, заявка, поиск, товары по id; cron синхронизации
src/proxy.ts             защита /admin (проверка cookie сессии)
src/components/ui        кнопки, поля, модальное окно, панель, табы, карусель, пагинация…
src/components/admin     UI-кит и экраны админки
src/lib/admin            типы домена, подписи статусов, права, доменная логика, server actions
src/lib/account          кабинет покупателя: server actions, разбор логина (телефон / e-mail), клиентский хук
src/lib/server/account   cookie сессии покупателя и проверка входа (DAL)
src/lib/server/db        подключение к MongoDB, коллекции и индексы, репозитории, демо-сид
src/lib/server/catalog   документы товаров, запросы витрины, кеш справочников
src/lib/server/suppliers/ddtuning  клиент API, курсы, маппинг фида, синхронизация, демо-импорт
src/lib/server/auth      пароли (scrypt), сессии, DAL (requireUser / requireActor)
src/lib                  каталог, форматирование, клиентское хранилище, настройки магазина
src/data                 переводы категорий поставщика, статьи блога, демо-каталог
tests                    vitest
```

Корзина, избранное, выбранное авто и просмотренные товары хранятся в браузере (localStorage);
заказы и профиль покупателя — в базе (кабинет), учёт заказов ведётся в админке.

## Что не входит в текущую версию

Онлайн-оплата (статус оплаты менеджер отмечает вручную), восстановление пароля покупателя по e-mail/SMS,
создание ТТН через API «Новой Почты» (есть ручной ввод номера и проверка статуса),
автоматическая отправка заказов поставщику по API (закупки оформляются в разделе «Закупівлі»).
